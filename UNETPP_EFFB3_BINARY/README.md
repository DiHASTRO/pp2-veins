# Три бинарные модели на основе UNETPP_EFFB3

Итоговая объединённая версия с речными CBAM/RAFF и всеми пятью классами:
[UNETPP_EFFB3_RIVER_ENSEMBLE](../UNETPP_EFFB3_RIVER_ENSEMBLE/README.md).
Этот каталог сохраняет предыдущие отдельные plain UNETPP_EFFB3 эксперименты.

Самостоятельный эксперимент: три независимые сети UNet++ с EfficientNet-B3,
каждая учится отличать одну положительную группу от всего остального.

| Задача | Положительные ID исходной маски | Отрицательные ID | Класс модели | Runner |
| --- | --- | --- | --- | --- |
| Вены + пересечения | 2, 3 | 0, 1, 4 | `UNetPlusPlusEffB3VeinsCrossings` | `run_pipeline_effb3_veins.py` |
| Артерии + пересечения | 1, 3 | 0, 2, 4 | `UNetPlusPlusEffB3ArteriesCrossings` | `run_pipeline_effb3_arteries.py` |
| Пересечения | 3 | 0, 1, 2, 4 | `UNetPlusPlusEffB3Crossings` | `run_pipeline_effb3_crossings.py` |

Зелёные участки входят в обе сосудистые цели и в отдельную цель пересечений.
Три маски поэтому могут пересекаться. Они не объединяются автоматически
в одну взаимоисключающую маску из пяти классов.

Исходные RGB-маски, `common/data_preparation.py`, settings и существующие runners
сохранены. Преобразование пяти исходных меток в две происходит внутри модели.
Новые runners повторяют прежние шаги обучения и оценки; при оценке они
применяют ту же положительную группу к ground truth и сохраняют только
метрики целевого класса.

**Перед длительным обучением:** в существующем разбиении обнаружены повторные
изображения одновременно в train и test. Код подготовки сохранён по условию,
поэтому новые runners наследуют эту проблему. Они пригодны для пробного
запуска, но для достоверного сравнения сначала нужно исправить разбиение
и заново оценить исходную модель. Подробности и точные числа ниже.

## Запуск с нуля в Windows PowerShell

Инструкция рассчитана на Windows 10/11, 64-битный Python и PowerShell.
Все команды ниже выполняются из корня проекта, в примерах это `E:\pp2-veins`.
Если проект расположен в другой папке, замените этот путь на свой.
Выполняйте блоки по порядку; при ошибке сначала устраните её.

Нужны папка проекта с `common`, `UNETPP_EFFB3_BINARY` и `run_pipeline_effb3_crossings.py`,
а также размеченный датасет. Установленный Python и готовый `.venv` заранее
не требуются. Для установки библиотек и первой загрузки ImageNet weights нужен
интернет. Для обучения рекомендуется NVIDIA GPU; вариант с CPU приведён ниже.
Для ручной проверки используется RTX 3060 с 12 ГиБ памяти.

### 1 Установите Python

Откройте [страницу Python 3.12.10](https://www.python.org/downloads/release/python-31210/),
найдите раздел Files и скачайте **Windows installer (64-bit)**.
Это версия Python, использованная для проверки модели.

Запустите установщик, включите **Add python.exe to PATH** и установку launcher
`py`, затем выберите **Install Now**. После установки откройте новое окно
PowerShell и проверьте:

```powershell
py -3.12 --version
```

Ожидается `Python 3.12.10`. Если команда `py` не найдена, закройте и снова
откройте PowerShell. Если это не помогло, повторно запустите установщик Python
и включите Python Launcher.

### 2 Откройте папку проекта

Получите папку проекта с кодом и данными, например распакуйте предоставленный
архив в `E:\pp2-veins`. Затем выполните:

```powershell
Set-Location -LiteralPath 'E:\pp2-veins'
Get-Location
Test-Path -LiteralPath '.\run_pipeline_effb3_crossings.py'
Test-Path -LiteralPath '.\UNETPP_EFFB3_BINARY\requirements.txt'
```

Две последние команды должны вывести `True`. Не запускайте обучение из папки
`UNETPP_EFFB3_BINARY`: относительные пути результатов рассчитаны на корень проекта.

### 3 Создайте виртуальное окружение

`.venv` — отдельная папка с Python и библиотеками этого проекта.
Если её ещё нет, создайте её:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print('venv:', sys.prefix != sys.base_prefix)"
```

Ожидается путь `E:\pp2-veins\.venv\Scripts\python.exe` и `venv: True`.
Если `.venv` уже существует, работает и использует Python 3.12, создание можно
пропустить. Если в нём другой Python, сохраните старое окружение и создайте
новое командой `py -3.12 -m venv .venv-binary`. В этом случае во всех дальнейших
командах замените `.venv` на `.venv-binary`.

Дальнейшие команды прямо вызывают Python из `.venv`, поэтому активация
не обязательна. Такой способ описан в [документации Python venv](https://docs.python.org/3.12/library/venv.html)
и работает независимо от разрешения запускать `Activate.ps1`.

### 4 Установите PyTorch

Сначала обновите pip внутри созданного окружения:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

Выберите **один** из двух вариантов установки PyTorch.
Команды соответствуют [официальной инструкции для PyTorch 2.7.1](https://pytorch.org/get-started/previous-versions/#v271).

**Вариант A — NVIDIA GPU**, в том числе RTX 3060 из проверенной конфигурации.
Установите актуальный драйвер своей видеокарты с
[сайта NVIDIA](https://www.nvidia.com/en-us/drivers/) и проверьте, что система
её видит:

```powershell
nvidia-smi
```

После этого установите PyTorch с CUDA 12.8:

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
```

**Вариант B — CPU**, если совместимой NVIDIA GPU нет:

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cpu
```

Модель выбирает CPU автоматически, когда CUDA недоступна. Полное обучение
на CPU обычно существенно медленнее.

### 5 Установите остальные зависимости

Используйте файл с версиями, проверенными для новой модели:

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\UNETPP_EFFB3_BINARY\requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

`pip check` должен вывести `No broken requirements found`.
Файл содержит также выбранные версии torch и torchvision: уже установленная
сборка `2.7.1+cu128` или `2.7.1+cpu` удовлетворяет записи `torch==2.7.1`.
Корневой `requirements.txt` менять не требуется.

Проверьте окружение и импорт модели:

```powershell
$env:NO_ALBUMENTATIONS_UPDATE = '1'
.\.venv\Scripts\python.exe -c "import torch, segmentation_models_pytorch as smp; from common import settings; from UNETPP_EFFB3_BINARY.model import UNetPlusPlusEffB3Crossings; print('torch:', torch.__version__); print('SMP:', smp.__version__); print('CUDA:', torch.cuda.is_available()); print('DEVICE:', settings.DEVICE); print('MODEL:', UNetPlusPlusEffB3Crossings.get_model_name())"
```

Ожидаются SMP `0.5.0` и MODEL `UN-WCD-BINARY-CROSSINGS`. Для варианта NVIDIA ожидаются
`CUDA: True` и `DEVICE: cuda`; для CPU — `CUDA: False` и `DEVICE: cpu`.
`NO_ALBUMENTATIONS_UPDATE` отключает сетевую проверку новых версий библиотеки
в текущем окне PowerShell; преобразования изображений остаются прежними.

### 6 Подготовьте расположение датасета

Используйте существующие изображения и RGB-маски. Структура папок:

```text
E:\pp2-veins\
    run_pipeline_effb3_crossings.py
    common\
    UNETPP_EFFB3_BINARY\
        model.py
        requirements.txt
    dataset\
        images\
            001_G.png
            002_N.png
            ...
        masks\
            001_G.png
            002_N.png
            ...
```

Для каждого изображения нужен файл маски с тем же именем. Загрузчик использует
PNG из `dataset/images` и `dataset/masks`; JPG, отдельные папки train/test
или внешние датасеты этот runner не подхватывает. При исходных настройках
`FOLDS_NUM=3` и `TEST_SIZE=20` требуется не менее **60 пар**.

Цвета RGB-маски должны соответствовать `common/settings.py`:

| Класс | RGB |
| --- | --- |
| Фон | `(0, 0, 0)` |
| Артерии | `(255, 0, 0)` |
| Вены | `(0, 0, 255)` |
| Пересечения | `(0, 255, 0)` |
| Белый класс (ID 4) | `(255, 255, 255)` |

Проверьте число файлов и совпадение имён до запуска:

```powershell
.\.venv\Scripts\python.exe -c "from common import settings; images = {p.name for p in settings.DATASET_IMG_DIR.glob('*.png')}; masks = {p.name for p in settings.DATASET_MASK_DIR.glob('*.png')}; print('Images:', len(images)); print('Masks:', len(masks)); print('Required pairs:', settings.FOLDS_NUM * settings.TEST_SIZE); print('Images without mask:', sorted(images - masks)); print('Masks without image:', sorted(masks - images))"
```

Числа Images и Masks должны совпасть и быть не меньше Required pairs.
Оба списка отсутствующих пар должны быть `[]`. В текущем проекте есть 100 пар.
Resize, Normalize, аугментации и создание folds выполняет существующий код;
заранее изменять размеры изображений или переписывать подготовку данных не нужно.

### 7 Запустите нужный эксперимент

Окружение достаточно создать и установить один раз для всех трёх задач.
В новых runners установлено `USE_FITTED = False`. Выполните нужную команду:

Вены вместе с пересечениями:

```powershell
.\.venv\Scripts\python.exe -u .\run_pipeline_effb3_veins.py
```

Артерии вместе с пересечениями:

```powershell
.\.venv\Scripts\python.exe -u .\run_pipeline_effb3_arteries.py
```

Отдельно пересечения:

```powershell
.\.venv\Scripts\python.exe -u .\run_pipeline_effb3_crossings.py
```

Запускайте их по очереди, после завершения предыдущего процесса.
Каждая команда обучает три fold-модели по 50 эпох, затем считает метрики.
Все три задачи вместе — девять обучений. Обучение автоматически не запускается
при импорте `UNETPP_EFFB3_BINARY.model`.

Первый конструктор загружает ImageNet weights EfficientNet-B3, если их нет
в локальном cache. Дождитесь строк `Epoch 1/50` и не закрывайте PowerShell
до завершения. Loss, его веса и число положительных/отрицательных пикселей
выводятся в консоль. Положительная группа указана как `Positive source IDs`.

Результаты сохраняются в отдельные автоматически создаваемые папки:

| Задача | Папка | Положительная группа в CSV |
| --- | --- | --- |
| Вены + пересечения | `UNETPP_EFFB3_BINARY/veins_crossings/` | `veins_*` означает ID 2 **или** 3 |
| Артерии + пересечения | `UNETPP_EFFB3_BINARY/arteries_crossings/` | `arteries_*` означает ID 1 **или** 3 |
| Пересечения | `UNETPP_EFFB3_BINARY/crossings/` | `crossings_*` означает только ID 3 |

В каждой папке: `weights_1.eth`, `weights_2.eth`, `weights_3.eth`,
`raw_metrics.csv` и `interval_metrics.csv`.
Исходные веса UNETPP_EFFB3 и результаты RIVER находятся в своих папках.

Пример чтения результатов:

```powershell
Import-Csv -LiteralPath .\UNETPP_EFFB3_BINARY\veins_crossings\raw_metrics.csv | Format-Table
Import-Csv -LiteralPath .\UNETPP_EFFB3_BINARY\arteries_crossings\raw_metrics.csv | Format-Table
Import-Csv -LiteralPath .\UNETPP_EFFB3_BINARY\crossings\raw_metrics.csv | Format-Table
```

Повторный запуск с `USE_FITTED = False` перезаписывает результаты именно выбранной
задачи. Сохраните копию этой папки заранее, если предыдущий запуск нужен.

### 8 Оцените уже обученную модель

Нужны все три файла весов выбранной задачи, тот же датасет и настройки разбиения.
Например, для вен откройте:

```powershell
notepad .\run_pipeline_effb3_veins.py
```

Измените `USE_FITTED = False` на `USE_FITTED = True`, сохраните и выполните:

```powershell
.\.venv\Scripts\python.exe -u .\run_pipeline_effb3_veins.py
```

Так же работают runners артерий и пересечений. Режим загружает веса и пересчитывает
CSV, а не продолжает прерванное обучение. Checkpoint содержит положительные ID,
порог, число выходных классов, веса loss, модель и Adam. Веса другой бинарной
задачи, исходной пятиканальной модели или RIVER отклоняются при загрузке.

### Ошибки запуска

| Симптом | Действие |
| --- | --- |
| `py` не найден | Установите Python 3.12 с launcher и откройте новое окно PowerShell |
| `.venv\Scripts\python.exe` не найден | Проверьте текущую папку и выполните шаг 3 |
| `No module named ...` | Установите requirements через Python этого venv |
| `No matching distribution found` | Проверьте Python 3.12, 64-битную архитектуру и доступ к выбранному pip index |
| CUDA недоступна при наличии NVIDIA GPU | Проверьте `nvidia-smi` и `torch.__version__`; переустановите torch/torchvision из CUDA index шага 4, затем выполните шаг 5 |
| `CUDA out of memory` | Закройте другие процессы GPU; при необходимости уменьшите `BATCH_SIZE` в settings до 4 или 2, учитывая изменение параметров сравнения |
| Не хватает изображений | При текущих настройках нужны минимум 60 PNG-пар; выполните проверку шага 6 |
| Ошибка загрузки encoder weights | Проверьте интернет и доступ к хранилищу pretrained weights |
| `Checkpoint does not match ...` | Выберите checkpoint именно этой задачи с теми же положительными ID |
| Веса не найдены | Завершите обучение всех folds перед `USE_FITTED = True` |
| `train fold must contain both positive and negative pixels` | В train fold отсутствует одна из двух целей; проверьте состав данных и цвета масок |

## Достаточно ли датасета

Аудит локальных 100 PNG-пар: имена изображений и масок совпадают,
неизвестных RGB-цветов в масках нет. После штатного nearest-neighbor resize
до 512×512 получены следующие числа:

| Цель | Изображений с положительными пикселями | Положительных пикселей | Доля всех пикселей |
| --- | ---: | ---: | ---: |
| Вены + пересечения | 100 | 1 311 059 | 5,0013% |
| Артерии + пересечения | 100 | 1 108 233 | 4,2276% |
| Пересечения | 100 | 46 187 | 0,1762% |

Разметка позволяет начать обучение без новых масок. Сто изображений достаточно
для исследовательского эксперимента, но не доказывают достаточность данных
для высокой точности или устойчивого переноса на другую камеру.
Обучение трёх сетей использует те же 100 снимков, а не 300 независимых примеров.

Пересечения особенно малы: медиана площади связного зелёного компонента
после resize — 8 пикселей. Связный компонент не обязательно соответствует
одному анатомическому пересечению. Бинарная постановка не добавляет
пространственных деталей, потерянных при уменьшении исходника.

По именам, цветам, размерам и распределению суффиксов локальные данные
совпадают с описанием Fundus-AVSeg: 100 файлов, N=40, D/A/G по 20,
размеры 1280×1280 и 2656×1992. Это вывод по признакам, а не проверка provenance.
В [первичной статье Fundus-AVSeg, Scientific Data 2025](https://www.nature.com/articles/s41597-025-05381-2)
авторы обучали в том числе U-Net++, используя patches, и отметили сложность
пересечений. Их результаты нельзя переносить на наш resize всего изображения.

В той же статье **белый цвет означает сосуды неопределённого типа**.
Если локальные маски взяты из Fundus-AVSeg без изменения, название
`capillaries` для ID 4 в settings не соответствует исходной семантике.
Настройки не переименованы; во всех трёх задачах ID 4 относится к «остальному».

## Ограничение существующего разбиения

`common/data_preparation.py::_shuffle_both_equally` использует
`np.random.randint(0, length, length)`. Это выборка с возвращением,
а не перестановка: исходники повторяются и часть вообще не используется.

При текущих 100 парах и `SEED=42` в общем списке остаётся 61 уникальный исходник:

| Fold | Записей train / test | Уникальных train | Уникальных test | Одни и те же исходники в train и test |
| --- | --- | ---: | ---: | ---: |
| 1 | 80 / 20 | 54 | 18 | 11 |
| 2 | 80 / 20 | 54 | 18 | 11 |
| 3 | 80 / 20 | 54 | 19 | 12 |

Это утечка между обучением и тестом. Она относится и к прежним экспериментам;
по таким метрикам нельзя надёжно оценить качество на новых снимках.
Подготовка данных сохранена по условию пользователя. Для достоверного сравнения
нужны разделение без повторов между train/test и повторная оценка baseline
и бинарных моделей на одном исправленном разбиении.

## Архитектура и обучение

RGB → EfficientNet-B3 с ImageNet initialization → штатный UNet++ decoder →
два logits: «остальное» и «положительная группа». Attention-модулей RIVER здесь нет.
Логика модели самостоятельная, без импорта моделей UNETPP_EFFB3/RIVER.

У каждой сети 13 624 938 параметров. Ручная проверка на реальных изображениях
512×512 прошла для всех трёх целей: один batch обучения, предсказание при B=1,
сохранение/загрузка модели и Adam, отклонение checkpoint другой задачи.
Дополнительно проверены три последовательных шага batch=8 при удержании
трёх fold-моделей на RTX 3060: пиковая выделенная CUDA-память на третьем шаге
составила 11 649 МиБ. Это проверка отдельных шагов, а не завершённое обучение
по 50 эпох; свободной памяти остаётся мало. Полный эксперимент не запускался.

Сохранены исходные Resize 512, ImageNet Normalize, аугментации, Adam,
learning rate `1e-4`, 50 эпох и сумма Weighted CE + multiclass Dice.
Внутри каждой сети multiclass Dice применяется к **двум** взаимоисключающим
классам. Это бинарная сегментация, несмотря на название режима loss.

Веса вычисляются только по train loader после объединения положительных ID:
`1/sqrt(freq)` с нормировкой среднего веса к 1. Отдельного усиления recall,
Focal, Tversky и connectivity loss нет. Прежнее взвешивание редкого класса
само по себе может стимулировать ложные положительные ответы;
бинарная задача не гарантирует улучшение Precision.

Выход `predict_probabilities()` — CPU float [B,H,W] с вероятностью положительной
группы. `predict_binary()` возвращает CPU long 0/1.
`predict()` возвращает CPU long [B,H,W], значения 0 либо исходный
репрезентативный ID: 2 для вен+пересечений, 1 для артерий+пересечений,
3 для пересечений. Размер batch сохраняется и при B=1.

Порог по умолчанию фиксирован: вероятность > 0,5. Его можно задавать
в конструкторе и он сохраняется в checkpoint. Автоматического подбора нет:
текущий runner не передаёт validation loader в fit, поэтому
`save_best=True` не выбирает лучшую эпоху — сохраняется результат 50-й.
Если отдельный validation loader передан вручную, лучшая модель и Adam
восстанавливаются вместе.

## Как сравнивать с пятиканальным baseline

Для каждой задачи сравнивайте Precision, Recall, Dice и IoU **одной и той же
положительной группы**, на одном разбиении и при одинаковых аугментациях.
CSV исходной модели для `veins_*` считает только ID 2; новый CSV считает
ID 2 или 3. Эти числа напрямую несопоставимы.

Для оценки baseline по новым целям необходимо заново получить его предсказания
и применить `ModelClass.targets_for_metrics()` **и к baseline predictions,
и к исходной разметке**, затем вызвать существующий `metrics.get_all_metrics`.
Это объединит исходные ID 2/3 или 1/3 по тому же правилу, что и у бинарной модели.
Для отдельной цели ID 3 прежние per-class метрики имеют тот же смысл,
но проблема разбиения остаётся.

Accuracy при редкой цели может быть высокой даже при пропущенных объектах.
Не подбирайте порог по test-fold и не сравнивайте средние между пятью
исходными и двумя бинарными классами. Независимые сосудистые маски
могут иметь дополнительные пересечения вне зелёной разметки; для итоговой
единой пятицветной маски потребуется отдельное правило разрешения конфликтов.

независимых моделей для ретинальных сосудов; это проверяемый эксперимент.
